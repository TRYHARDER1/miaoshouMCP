# 商品编辑模块需求基线

依据 2026-11-08 的《MCP流程介绍》最终讨论，以及此前妙手开放接口实测结果。

## 业务闭环

选择国家与店铺、读取采集箱商品、保存原始快照、分析与优化内容、翻译 SKU、处理图片、计算价格、预览审批、合并完整对象保存、重新读取逐字段校验，最后进入后台人工审核。

## 冻结规则

1. 定价模板 ID 为 `1953645`，名称为“新加坡利润40%”，计算采用实际配置 `profitPercent=30`。模板 ID、名称、配置与公式对照结果应进入定价快照。
2. 商品与各 SKU 重量从原始快照各自增加 `0.01 kg`。SKU 重量缺失或为空时使用原始商品重量兜底。商品原始重量也缺失时阻断。使用 BigDecimal，重复处理同一快照保持相同结果。
3. 包装尺寸来自真实商品数据或人工配置。前期某个测试商品的暂定 10 cm 不是全局默认值。
4. 修改规格展示文字时原样保留 attrId、attrValueId、SKU Map Key 和组合关系。
5. 商品属性初期允许修改 valueName，attributeName 的实测未持久化，作为限制字段处理。
6. 描述按 DOM 文本节点构造和验证，处理实体解码风险，长度上限 10000，标题长度 25–255。
7. 价格公式使用确定性计算，并逐 SKU 与 ERP 定价引擎结果对照；通过前仅预览。
8. 图片处理覆盖主图、详情图和 SKU 图，保持产品真实外观与正确引用。Muse 图片生成处理与图片空间上传分别记录副作用。

## 初版验收范围

M0 设计基线、M1 MCP 与 API 基础、M2 店铺与采集箱读取、M3 原始快照和 SKU 校验，加上重量草稿与差异预览。业务草稿基于保留未知字段的原始 JSON 深拷贝。

内容优化、关键词研究、Muse、定价复现、审批保存、全量回读与批量流程按后续里程碑验收。

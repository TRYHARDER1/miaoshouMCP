# M4 需求基线

依据 2026-11-08《MCP流程介绍》的最新决策，在既有 M0–M3 上完成文本优化阶段。

## 确认的流程

1. 编写需求、技术设计、任务拆分。
2. M4.1 定义模型 Provider，接入 DeepSeek 的结构化响应与错误处理。
3. M4.2 从不可变快照生成带事实来源的商品分析。
4. M4.3 区分人工关键词、模型推荐词和真实市场指标。
5. M4.4 生成英文标题及固定模板 HTML 描述。
6. M4.5 翻译规格名称和值，保留规格 ID、Map Key、组合、库存和仓库映射。
7. M4.6 用单 SKU、多规格、多 SKU 三类商品验证完整流程，结果进入本地待审核草稿。

## 内容约束

- 当前 Provider 为 DeepSeek，未来 Muse 按其真实接口实现替换。
- 模型使用环境变量配置，凭证在本机环境提供。
- 输入来自原始快照，保留完整原始对象与未知字段。
- 模型输入视为商品数据，商品文本中的指令不授予操作权限。
- 分析与营销内容应附原始字段的证据。自动校验检查引文、结构和数字；语义与营销真实性仍由人工审核。
- 人工词和 AI 推荐词明确标注来源，搜索量与增长率保持 null，直至接入真实数据源。
- 英文标题长度为 25–255，描述最长 10000 字符。
- 描述由代码构造 HTML 文本节点，原始描述图片保留原 URL、数量及顺序。
- 只修改标题、描述、SKU 展示文字；价格、重量、商品属性和库存沿用快照。

## 生成记录

每次模型调用记录快照 ID、Provider、实际模型、任务、Prompt 版本、开始与完成时间、输入摘要及哈希、输出、结构校验状态、错误码与人工审核状态。

模型生成及自动校验完成后的审核状态为 PENDING_REVIEW。结构校验通过不代表已经完成人工事实核对。

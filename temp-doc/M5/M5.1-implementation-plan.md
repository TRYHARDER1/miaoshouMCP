# M5.1 实施计划

日期：2026-11-08。来源：用户指定《MCP流程介绍》最终 M5.1 计划。

## 范围与停止点

本阶段仅实现 `product_image_extract_assets(snapshotId)`：读取已有本地不可变快照，提取图片资产及所有引用位置，进行本地 URL 校验并返回可重复生成的清单。完成 M5.1 后停止，不进入 M5.2。

不访问网络，不下载、调用 Muse、上传、替换、创建草稿、保存商品或发布；不增加数据库表，不修改 M4 HTML 构造器。

## 开发前已核对事实

已阅读 README、任务清单、现有快照服务、SKU 校验器、内容服务、HTML 构造器及工具注册方式。现有三类真实快照中 SKU 图片均位于 `skuPropertyList[].attrValueList[].imgUrl`；`skuMap` 中没有 `imgUrl`。此处与计划假设不一致。按计划要求暂停 SKU 分支并向用户反馈，等待确认实际字段适配；其他分支可继续。

`imgUrls` 只有顺序，没有独立主图标记。未经确认的商品图归类 UNCLASSIFIED，第一张只标识主图候选，不当作已确认 MAIN_IMAGE。

## 修改清单与顺序

1. 新建 `domain/image` 不可变模型，区分去重 Asset 与物理 Reference。
2. 新建提取服务：商品图片、Jsoup 详情图片、本地 URL 校验、稳定 SHA-256 资产 ID、计数和问题路径；SKU 分支待确认后按真实结构实现。
3. 新建独立 MCP 工具并注册；参数只接收快照 ID。
4. 合成测试覆盖空图片、重复引用、非法 URL、畸形 HTML、查询参数、顺序、稳定 ID、不可变性；通过后执行既有回归。
5. 使用已有三类本地快照执行 STDIO 验收，核对数据库及原始 JSON 未变化。
6. 完成字段映射、设计、需求、任务及测试报告；凭证扫描后提交和推送现有仓库。

## 计数与错误约定

`totalAssets` 为不同原始 URL 的数量；`totalReferences` 为非空来源位置数量。一个规格图片位置关联多个 SKU 时仍是一条物理引用，引用携带所有原始 Map Key。空值显式计入 skippedEmptyReferences；非空非法 URL 保留为 INVALID_URL 资产和引用，并使 validation.valid=false。错误只返回位置和错误码，不复制 URL。

资产 ID 为 SHA256(snapshotId UTF-8 + NUL + originalUrl UTF-8)，内容哈希 sha256 在未下载阶段为 null。URL 不做规范化、裁剪或删除查询参数。摘要按引用角色计数，角色总和等于 totalReferences。

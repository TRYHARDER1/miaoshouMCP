# M5.4 Muse 图片结果下载与完整性校验需求

状态：已批准并完成代码与技术测试；真实 Muse 输出验收待补。规划基线 `68064ae`，2026-11-08；旧 M5.3 的 129 项是历史基线，当前执行结果见 M5.4-test-report.md。

后续批准与实施：用户明确确认开始修改，按 Q1–Q5 推荐策略实施首版；用户另选择先完成开发与技术测试，真实 Muse 输出验收待补。代码及实际测试见 M5.4-test-report.md。本文保留原需求与决策记录，不把公开图片夹具认定为真实 Muse 优化结果。

## 1. 目标与边界

将已登记的 Muse 结果链接转换为本地独立文件，建立 `assetId → original → 已登记结果 → processed` 的稳定对应。只接受 batchId/assetId 等内部标识，URL 从数据库取；不提供任意 URL/本地路径下载接口。允许只下载已部分登记的资产，不为未登记资产制造失败记录。

仅负责安全获取、技术完整性检查和本地持久化。不调用 Muse/API/网页，不生成新 Muse 任务，不上传图片、不写商品/草稿、不发布、不调用多模态视觉评审，不进入 M5.5，不改 M5.1/M5.2 核心规则或人工等待租期。

技术完整性通过只表示协议、字节和图片容器/解码检查通过；不能证明颜色、规格、数量、英文语义、SKU 外观或营销质量正确。视觉审核始终 NOT_REVIEWED。

## 2. 已有事实与二次提炼

- M5.3 的 ms_muse_result 只登记链接，状态只能 LINK_REGISTERED，download_verified 有 CHECK=0。
- 当前链接一经登记不允许换成不同 URL；签名链接过期如何更换是尚待确认的业务缺口，不可直接 SQL 覆盖。
- 一个 assetId 可能带多个 SKU 引用，但只下载一份对应结果；多个 assetId 即使文件摘要相同也保持独立路径和关联，不静默合并。
- 当前安全下载实现只用于原图。可复用 SafeImageSource 的校验/解析策略，但不能伪造 ImageAsset 来下载结果，也不能仅凭登记时的 URL 语法校验认定实际访问安全。
- 历史包固定 v1，完整 internal manifest 保持本地；对外交付修正按独立安全审查提案审批。

## 3. 功能要求与验收含义

| 编号 | 要求 | 验收 |
| --- | --- | --- |
| R01 | 只处理当前 job 中已登记且属于该 batch 的资产 | 跨 job/batch/asset 拒绝；URL 不能来自工具输入或投影文件 |
| R02 | 公网 HTTPS/443，DNS 全部结果检查并固定 IP，逐跳检查 | 本机/私网/元数据/保留地址、混合 DNS、重绑定和降级均拒绝；TLS 不放宽 |
| R03 | 有界连接/响应/总时长/传输字节/解码资源 | 声明超限和无 Content-Length 实际超限均拒绝；失败/重定向响应也受限 |
| R04 | MIME、签名、容器结构、真实解码、尺寸和大小验证 | 空、HTML 冒充、截断、损坏、异常 warning、未知格式不标为 VALIDATED |
| R05 | 原图和结果图分别保留，记录关联和 SHA-256 | assetId/源链接摘要/原图摘要/结果摘要对应一致；不覆盖其他资产 |
| R06 | 幂等及并发 | 同资产有效文件不重复联网；并发只一持有者；同字节多资产不复用路径 |
| R07 | 任务及文件可恢复 | 完成下载的本地阶段可续接；发布后提交前中断可校验补记；半文件不当作完成 |
| R08 | 失败明确、重试受控 | 不自动更换 URL 或无限重试；旧 worker token 不能发布；损坏已发布文件不能静默覆盖 |
| R09 | 状态独立 | 不更新 ms_muse_result 约束字段，不更改 M5.2 状态/lease；只写 M5.4 新表 |
| R10 | 查询与审计 | 区分缺链接、未开始、处理中、技术通过、失败、文件失效；只记录安全错误码 |

## 4. 已批准的初版策略

默认沿用 JPEG/PNG、每图 8 MiB、4000 万像素、单边 20000；DNS 4 秒、连接 5 秒、响应 10 秒、单跳 20 秒，最多 3 次重定向。建议单资产下载总预算 120 秒、全局最多 2 个网络/解码工作位、批次内部依序处理。不得把解码线程的调用方超时宣传为已强制终止底层工作。

结果处理状态独立：PENDING、DOWNLOADING、DOWNLOADED、VALIDATING、VALIDATED、FAILED。没有处理行代表 NOT_STARTED；未登记链接代表 MISSING_LINK。VALIDATED 与 `integrityVerified=true` 需本地文件仍与通过校验的摘要一致，视觉状态仍 NOT_REVIEWED。M5.3 接口继续返回自己的 downloadVerified=false，新阶段接口明确区分该登记语义。

部分资产失败不回滚其他资产的成功；原子性以单资产一次发布为单位。异常恢复以本地已完成阶段为断点，首版不实现 HTTP Range 字节续传。没有完成凭据的半文件只能显式重试从头获取，不追加拼接。

## 5. 持久化要求

建议仅新增“结果处理当前状态”和“状态事件”两表，对现有 M5.3 登记建立复合外键，保留原 schema 和含义。不重建 ms_muse_result，不将 download_verified 改为 1。DDL 是技术设计中的审核草案，本次未写入 schema.sql 或执行。

目录推荐 `processed/{assetId}/{assetId}.{ext}` 加每资产完整性凭据，同一私有根目录内 staging 原子发布，原图和历史任务包文件保持原值。有效已存在文件直接复用；损坏或冲突明确阻断。哈希只用于内容完整性及重复提示，不能证明视觉对应正确。

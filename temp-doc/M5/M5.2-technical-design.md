# M5.2 技术设计（编码前确定）

## 已核对事实

已阅读 README、总任务、M5 需求/设计/任务、M5.1 计划/映射/报告；检查提取器、图片服务、清单/引用 DTO、SQLite schema、现有 MyBatis Mapper、事务与工具注册。现有 assetId 基于 snapshotId+原 URL，M5.2 不重定义身份。M5.1 含非法 URL 时 validation=false，因此本阶段整体拒绝，并非静默过滤后创建完整计划。当前只有快照/草稿/模型记录表，需新增三张调度表。

## 创建、查询及幂等

先调用 ProductImageService.extract，拒绝结构错误，按 assetId 检查重复，保留清单顺序。校验后在一个事务中写入计划、批次和任务。snapshot_id 唯一；plan_id+asset_id 主键；plan_id+sequence、plan_id+批次序号唯一；复合外键阻止跨计划挂接。refs/URL 不复制到明细，查询时从原快照重建完整 M5.1 资产。

计划保留 manifest_hash（整个清单确定性 JSON 的 SHA256），查询及重复创建校验它，防止提取器升级后静默丢失关联。batchSize 默认 4；已有计划且省略 batchSize 时复用原值，显式大小冲突拒绝。

沿用 MyBatis 与 Spring 事务，使用 TransactionTemplate。所有调度事务先执行过期任务 UPDATE（即使无命中也先取得 SQLite 写锁），之后才读取计划/状态，避免并发 DEFERRED 读事务升级锁导致重复或 SQLITE_BUSY_SNAPSHOT。连接 busy_timeout=5000；失败整笔回滚并返回 BATCH_STORAGE_FAILED，无 SQL/URL 原文。无需新增队列、外部依赖或全局锁表。

## 状态机与恢复

普通批次状态由任务聚合：存在 PROCESSING→PROCESSING；否则存在 FAILED→FAILED；否则存在 PENDING→PENDING；其余→COMPLETED。PAUSED、CANCELLED 为显式覆盖状态。

| 动作 | 规则 |
| --- | --- |
| 领取（内部服务） | PENDING→PROCESSING，仅未暂停/取消批次；生成新尝试 token 和期限 |
| 心跳（内部服务） | 当前未过期 token 续期，不创建任务 |
| 结果（内部服务） | PROCESSING→COMPLETED/FAILED/SKIPPED，匹配当前未过期 token；相同终态同 token 回放幂等 |
| 暂停 | PENDING/PROCESSING/FAILED→PAUSED；重复暂停幂等；保留任务状态 |
| 恢复 | PAUSED→当前任务聚合状态；重复恢复到 PENDING 幂等 |
| 取消 | 非完成批次→CANCELLED；未完成任务→SKIPPED，旧尝试失效；重复取消幂等 |
| 重试 | 未暂停/取消批次中 FAILED→PENDING，retry_count+1，复用原任务，保留完成行 |
| 异常恢复 | 已到 lease_until 的 PROCESSING→FAILED/LEASE_EXPIRED，不自动重新处理 |

租期通过 image-batch.lease-seconds 配置，默认 1800 秒，限制 1–86400。启动后及每个调度操作检查超时。未到期限的处理中任务继续保持，避免另一实例启动误抢有效任务；到期后下一次查询或恢复操作使其进入明确可重试状态。心跳供未来执行流程调用，本阶段不启动执行器。暂停不假装取消已发生的外部工作，取消/超时的旧 token 不得覆盖新状态。数据库内幂等不等于未来外部 Muse 的 exactly-once；重试前需核对外部结果。

## 持久化与字段约定

完整可执行 DDL 与逐字段注释写在 src/main/resources/schema.sql。三个表：ms_image_batch_plan（快照唯一计划、大小、清单摘要、资产数量、时间）；ms_image_batch（计划内有序批次、状态、时间）；ms_image_batch_task（资产关联、序号、状态、错误码、重试次数、尝试 token、租期、开始/完成/创建/更新时间）。时间均为 UTC ISO-8601，同一固定时钟格式用于租期比较。DDL 只追加，不修改 M0–M5.1 表。

## 工具与边界

新增创建、查询、进度、单批暂停/恢复/取消，以及计划整体暂停/恢复、失败重试、过期恢复工具。查询用 snapshotId 或 batchPlanId，若两者都给出须一致。内部领取/心跳/结果 API 不暴露 MCP，避免在未处理图片时人为宣告已优化。进度按任务状态计数，remaining=pending+processing+failed，另外报告当前可领取数、暂停/取消批次数。totalSkipped 为已跳过资产任务数，不把空引用当成图片。

查询可能执行到期回收，因此属于本地调度状态维护；永远不修改快照、草稿或模型记录。完成后停止在 M5.2。

# M5.3 技术设计（安全分析先于编码）

## 只读核对事实与范围

已阅读 M5.1 映射/报告、M5.2 需求/设计/任务/报告、M5 任务；检查资产/引用、批次 Mapper/Service/Tools、SQLite 与文件管理。现有文件仅本地 `.data` 数据库，无安全图片下载器。真实样本已核对的商品图/规格图均为 HTTPS alicdn JPEG；M5.1 没有证明网络可达，本阶段须实际验证，失败不冒充已有原图。

原图文件是本阶段明确要求的交付物，所以新增仅用于原图的下载组件属于 M5.3 必要依赖。Muse 结果下载仍留到后续阶段。没有原图处理/优化、远程提交或额外基础设施。使用现有 Reactor Netty/WebClient 与 JDK ImageIO，不增加外部依赖。

## 原图下载安全方案

只接收已核对 M5.2 批次中的 M5.1 URL，不提供任意 URL 下载工具。仅 HTTPS/443、无 userInfo；拒绝本机/内网/元数据/保留地址与内部域名。DNS 查询用有界线程池与超时；解析出的全部地址均须为允许的公网地址，再将已核对 IP 固定到本次 Netty resolver，避免检查后再次解析带来的 DNS rebinding。禁用自动代理、连接池复用和自动重试；保留 TLS 主机名/证书校验，不使用信任所有证书。

最多 3 次重定向，每跳重新执行 URL/DNS/IP 检查，禁止降级。连接 5 秒、响应 10 秒、单跳总等待 20 秒，DNS 4 秒。每张最多 8 MiB，限制响应 Content-Length 和实际缓冲区；只接受 JPEG、PNG 的一致 Content-Type/文件签名/实际 ImageIO 解码，限制像素总数 4000 万。其他格式明确报不支持，不伪装成功。原图文件按稳定 assetId 命名，不用远程文件名，不重编码图片。

Reactor Netty 的 resolver/TLS/超时 API 依据官方文档核对：[HTTP Client](https://projectreactor.io/docs/netty/release/reference/http-client.html)、[Netty resolver](https://netty.io/4.1/api/io/netty/resolver/AddressResolverGroup.html)。下载异常不保留带原 URL 的底层异常正文；原图 URL 作为任务数据只在私有清单中出现。

## 持久化与一致性

M5.3 单独新增 job 和 result 两表，完整 DDL 及字段注释置 schema.sql。job 对 batch_id 唯一（当前版本固定 1）；result 对(job_id,asset_id)及 asset_id 唯一，规范化 URL 摘要全局唯一。规范化仅用于结果重复映射检查（host/scheme 小写、默认端口和 fragment 处理），保留提交原 URL；不擅自去除查询参数。

M5.2 读取使用只读 Mapper 与 M5.1 重建，不调用会回收租期的 ImageBatchService.get；校验原计划 manifest_hash 和全部任务映射。M5.3 不写 M5.2 三表。暂停、取消、处理中批次禁止新导出/交接/提交，结果历史仍可查询。

事务先写 M5.3 job 表取得 SQLite 写锁再读状态。原图下载放在事务之外；固定 jobId 加导出 token/期限，阻止并发重复下载与旧导出者提交。临时目录与最终目录位于同一私有根目录，成功后原子发布。文件系统和 SQLite 不假装具有共同事务：若发布后数据库提交前崩溃，重试通过 job.json/完整包及文件摘要恢复完成状态；若数据库已记录导出而文件缺失/损坏，明确拒绝，不静默覆盖或换版本。过期构建可重试，活动构建返回忙，遗留目录不擅自删除。

导出预约为 900 秒，仅保护原图获取，不是人工等待期限。完整目录已发布时可立即恢复，不必等预约过期。单个 manifest/Prompt 限制 2 MiB，超限在发布之前拒绝，避免产生自身无法读取的包。失败或中断的 `.staging` 目录不当作有效导出，不自动递归删除，后续可人工核对清理。

默认目录 `.data/image-jobs/JOB-{jobId}/`，包含 job.json、batches/BATCH-{batchId}/manifest.json、prompt.md、original/、result-links.json。所有目录/文件名只使用受控 ID，禁止越界及符号链接。导出根目录可配置为本地绝对路径。

result-links.json 是数据库结果的可重建投影。链接先事务登记；随后另起持锁事务按最新数据库内容原子更新投影。投影失败不丢已提交链接，返回 SYNC_PENDING，下一次查询/导出自动修复。数据库始终是链接事实来源。

## 状态及接口

人工交接状态独立于批次：CREATING、EXPORT_FAILED、EXPORTED、WAITING_MUSE、PARTIALLY_RECEIVED、LINKS_RECEIVED。不存在 job 相当于 NOT_EXPORTED。只有明确人工交接动作进入 WAITING_MUSE；登记数量决定部分/全部收到。结果始终 LINK_REGISTERED、未下载验证。没有自动把任何 M5.2 任务设为 COMPLETED。

新增 product_image_export_batch(batchId,version?)、product_image_mark_handed_off(batchId,version?)、product_image_submit_results(batchId,results,version?)、product_image_get_batch_results(batchId)。版本省略为 1，其余版本明确冲突，不自动升级。服务错误与事务错误脱敏，部分提交整笔原子性，冲突时不覆盖旧结果。

成功后停在 M5.3。未验证 supplementarySkuImageUrls 非空结构继续由 M5.1 拒绝。

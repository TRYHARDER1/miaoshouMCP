# M5.2 图片批次调度器测试报告

日期：2026-11-08。结论：M5.2 验收通过，到此停止，未进入 M5.3。

## 核心结果

- 快照唯一计划与计划内唯一资产任务，由数据库约束保证；并发创建不重复。
- 批次计划、分组与全部任务同一事务提交；创建或更新中断时整体回滚。
- 重复调用与重启读取原计划和进度，不重新分配；不同 batchSize 明确冲突。
- PAUSED 保留进度，CANCELLED 保留完成结果；FAILED 明确重试且只复用失败行。
- PROCESSING 使用持久化租期及尝试 token。过期后 FAILED/LEASE_EXPIRED，不自动派发；旧尝试不能覆盖重试或取消后的状态。
- 所有资产、分类、候选标记、sequence 和完整引用来自原 M5.1 清单，没有在批次表复制 references。

通过实际 initialize、tools/list、tools/call 验证全部 10 个新增工具。逐项比较任务中的完整 asset 与 M5.1 清单，包含所有 SKU Map Key、物理引用、顺序及 UNCLASSIFIED/候选标记；完全相同。STDIO stdout 仅有 JSON-RPC，普通日志输出到 stderr。

强制终止 Java 进程前，暂停第一计划、取消第二计划中的一批，并在第三计划的隔离数据库中注入已完成/过期处理中/未到期处理中状态，作为异常退出测试夹具；这些状态并不表示实际调用了 Muse。

重启后：全部 planId/batchId 不变，计划仍为 3、批次 18、任务 69；暂停及取消保留；已完成 1 个保留；过期 1 个自动变为 FAILED/LEASE_EXPIRED，retryCount 仍为 0；未到期 1 个保持 PROCESSING。明确重试只重排失败任务并增加其计数，未重复创建任务。原始快照、草稿、模型记录按完整内容摘要比较前后一致，原 M4 数据库也保持一致。

## 数据库与恢复语义

完整 DDL、字段类型/注释、唯一约束、索引及外键在 `src/main/resources/schema.sql`，仅新增 ms_image_batch_plan、ms_image_batch、ms_image_batch_task。所有新字段及状态模型有注释；事务先取得 SQLite 写锁，再读取状态，避免 DEFERRED 读事务升级锁竞争。失败返回 BATCH_STORAGE_FAILED，不回显 SQL、URL 或内部异常正文。

未过期 PROCESSING 在重启后保留；到期后下一次调度操作回收，租期默认 1800 秒。此策略避免另一进程启动误判仍有效的任务，但不会证明外部图片处理是否已发生。未来重试必须先核对外部结果；本阶段不提供外部 exactly-once 保证，也不自动将任何图片标记为已优化。

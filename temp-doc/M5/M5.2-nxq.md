# M5.2 需求

基于 M5.1 唯一资产建立可持久化的批次计划，每批默认 4、允许 1–4 张，不复制凑数；一张资产在一个快照计划中只分配一次。不同快照独立。保留资产 sequence、分类和所有原始引用；UNCLASSIFIED 与候选主图不升级分类。

同一 snapshotId 仅有一个计划，重试返回同一计划和状态。显式传入与原计划不同的 batchSize 返回冲突，不重新分组。重复请求未传大小时复用原配置。空资产生成持久化空计划。清单 validation=false 或含 INVALID_URL 时整体拒绝，不产生部分可执行计划。

批次状态：PENDING、PROCESSING、PAUSED、COMPLETED、FAILED、CANCELLED。任务状态：PENDING、PROCESSING、COMPLETED、FAILED、SKIPPED。支持单批及快照计划整体暂停、恢复，取消、失败重试、进度查询。商品级控制以不可变 snapshotId 的计划为边界，不误操作同商品其他快照。

暂停阻止新任务领取，保留现有处理中任务及已完成结果；恢复只取消暂停标记。取消保留完成结果，其余任务 SKIPPED，禁止继续执行。重试仅 FAILED→PENDING，复用原行并增加重试计数，不清除其他进度。

PROCESSING 使用持久化期限和尝试 token；异常退出后不盲目重新派发。启动及后续操作回收已过期任务为 FAILED/LEASE_EXPIRED，需明确重试；未过期状态继续保留。过期或旧 token 不能提交结果。不存在任务、非法流转、清单结构错误和数据库故障返回明确且脱敏的错误。

当前只维护调度状态；COMPLETED 不证明 Muse 优化或质量合格。没有执行器自动完成任务，没有图片处理、Muse、下载、上传、商品/草稿写入或发布。不进入 M5.3。

验收覆盖 T01–T20、单/4/26 SKU、多个商品及快照隔离、引用完整、并发、事务回滚、持久化与进程重启、过期恢复与旧尝试隔离；完整 Maven clean verify 及 STDIO 验收。

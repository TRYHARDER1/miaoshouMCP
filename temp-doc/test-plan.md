# 初版验收计划

## 自动化

| 场景 | 预期 |
| --- | --- |
| UTF-8 JSON HMAC 黄金向量 | 与独立 Python 结果一致 |
| 实际 HTTP 请求 | 发送字节与参与签名的字节一致 |
| HTTP 200 业务失败 | 抛出脱敏错误，发送次数为 1 |
| AES-GCM 密文及认证标签篡改 | 正常解密或拒绝篡改 |
| 重量多 SKU、null、缺失 | 独立增加 0.01，按商品原始重量兜底 |
| 重量为 0、商品重量缺失、增重溢出 | 阻断草稿 |
| 多维 SKU Key 顺序与维度顺序不同 | 正确解析 |
| 未知 ID、重复维度、重复组合、ID 变更 | 拒绝 |
| 合法稀疏组合 | 接受 |
| 缺失字段与 null、JSON Pointer 特殊字符 | 差异可区分 |
| SQLite 快照与并发草稿 | 原始不变、同一快照同一草稿 |

## 进程与真实接口

对打包 JAR 执行 initialize、tools/list、tools/call。检查 stdout 为 JSON-RPC；读取一份真实商品、捕获快照、生成重量草稿并重复调用，校验草稿 ID 与重量稳定。

使用调用方当前提供的凭证，凭证只传给进程环境。商品和数据库证据保留在本地，仓库使用合成测试样本。

## 下一阶段

完整保存需覆盖已审批多字段合并、最新 ossMd5 冲突、空尺码表处理、HTML 实体回读、逐 SKU 权重、恢复和重复提交。M4–M9 的验收结果随着实现更新。
